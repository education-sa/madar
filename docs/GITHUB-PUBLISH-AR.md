# رفع تحديثات مدار يدويًا

المجلد المعتمد للتطوير وGitHub Desktop: `/Users/abeer/Documents/GitHub/madar`
المستودع: `education-sa/madar` — الفرع `main`.

## الاستخدام
1. افتحي هذا المجلد في Codex كمشروع محلي، وراجعي التعديلات. تعليمات هذه المحادثة تشير إليه أيضًا.
2. من Finder افتحي ملف `رفع مدار إلى GitHub.command` داخل المجلد.
3. سيجلب أحدث main ويفحص الملفات دون رفع. اقرئي قائمة التعديلات، واكتبي رسالة Commit (أو Enter لرسالة مؤرخة).
4. اكتبي «رفع» للتنفيذ. أي جواب آخر يلغي العملية قبل Commit أو Push.

البديل داخل GitHub Desktop: اختاري المستودع الموجود في Documents/GitHub/madar، راجعي Changes، ثم اكتبي Summary واضغطي Commit to main وبعدها Push origin. هذه خطوتان منفصلتان في GitHub Desktop.

إذا فشل توثيق GitHub في مشغل الرفع، فالـCommit يبقى محليًا؛ استخدمي Push origin من GitHub Desktop المسجّل بحسابك. لم نقرأ أو نحفظ كلمة مرور أو Token، ولم نختبر Push فعليًا.

## الحماية
- الفحص قبل Commit وPush يعمل كذلك من GitHub Desktop بواسطة hooks محلية.
- منع ملفات البيئة والإعدادات الفعلية وسجلات الأخطاء والنسخ الاحتياطية وملفات المستخدمين، مع فحص أنماط أسرار شائعة. تظل مراجعة Changes مطلوبة؛ الفحص الآلي لا يضمن اكتشاف جميع أشكال المعلومات الشخصية.
- لا Force Push ولا حذف ملفات ولا نشر إلى استضافة، ولا رفع تلقائي بعد التعديلات.
- إذا تقدم GitHub أو ظهرت تعارضات يتوقف المشغل دون دمج أو استبدال عملك. استخدمي GitHub Desktop للمراجعة والدمج؛ لا تختاري Discard changes.
- hooks داخل .git محلية لهذا الجهاز؛ بعد أي Clone على جهاز جديد يلزم إعادة تثبيتها.
